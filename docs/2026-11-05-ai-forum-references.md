# AI 帖子/论坛类互动调研 — 第 1 轮（2026-11-05）

本对话专线：研究 AI 发帖 / 论坛类互动形态，为 JiuJiu-Crew（玖玖的 AI 群聊）提供可参考样本。
起点样本只有 Galatea Garden，本轮先把同类平台的版图铺开，后续逐个深挖互动细节。

状态说明：本轮为搜索核实 + 公开文档阅读，未实际注册/入驻任何平台。互动细节的深挖留待后续轮次。

## 1. Galatea Garden（起点样本，与 Crew 最像）

- 形态：论坛帖子 + Chat + 游戏回合，统一走 MCP 工具读写（服务端 `https://galatea.abysslumina.com/mcp`）；另有公开的「漂流瓶」交友信入口（无需 token 只能投瓶，借此认识 Garden 同伴、争取邀请）。
- 唤醒机制（关键）：本地唤醒桥订阅 Garden 的 SSE 事件，收到 `wake` 后经可替换的 Runtime Adapter 把消息注入 Codex、Claude Code 等运行时。
  - wake 的 reason 只有三类：`game_turn_required`（轮到你行动）、`forum_notification_available`（论坛有新动静）、`chat_notification_available`（有人提到你）。
  - wake 文案由服务端控制，人话且留有余地，如「花园里有新动静，去用 list_notifications 看看吧，想回就回。」
  - wake 只是提示，不是权威状态：被唤醒的 Agent 自己再调 MCP 的 `list_notifications` / `get_my_status` 读当前状态，SSE 事件本身不消费通知，重复唤醒安全。
- 安全策略：fail-closed。单次连接、断开即停、禁止自动重连/看门狗/定时拉起——因为生产环境曾遭单一来源 24 小时数百万次自动化连接，重连风暴会把单机故障放大成平台级负载。
- 组件边界：桥只管传输与透传，不懂业务、不管会话；每个运行时自己实现 Adapter。桥与 Adapter 代码分离。

对 Crew 的意义：这几乎就是 Crew 一直想做的「推送而非轮询 + 按名唤醒」的已落地版本，且验证了两个设计：
1. 唤醒 = 轻提示 + 事后自取权威状态，而不是把正文塞进唤醒通道；
2. 「想回就回」与 Crew「成员可发言也可沉默」的定位一致。

## 2. Moltbook（规模最大的 AI-only 论坛）

- 形态：Reddit 式。发帖、评论、投票、关注、主题子论坛（submolts）；人类只能围观，不能发帖。
- 接入：Agent 读一份 `skill.md` 即可自助注册，人类主人再经 X 做归属验证。
- 节奏：Heartbeat 机制，约每 4 小时醒来逛一轮；限流明确（发帖 1 次/30 分钟、评论 1 次/20 秒、每日评论上限 50）。
- 规模与研究：2026-01 上线，三周内百万级帖子；多篇论文分析指出其讨论高度自指、情绪偏正向、结构偏浅，少数高活跃账号主导；另有研究在 22.8 万帖中检出约 18% 含毒性/操纵/恶意内容（凭据窃取、诱导执行命令、推广未可信 skill 等）。

对 Crew 的意义：帖子/子论坛/限流/身份验证这套论坛骨架可借；但公开大规模 AI-only 的失控面（提示注入、刷屏、礼貌性附和）正是 Crew 这种小而私密、成员已知、授权名单制要避开的。限流数字本身也可参考：宁可慢，不刷屏。

## 3. Chirper.ai（最早的 AI-only 微博式）

- 形态：X/Twitter 式信息流。人类写一段人设描述，Agent 此后完全自主发帖、评论、关注、演化关系，人类不再干预。
- 研究数据：6.5 万+ Agent、770 万+ 帖；帖子比人类更长、emoji/@/# 用得更多；99.83% 的 @ 是提到不存在的 Agent（幻觉式社交）；约 31% 的 Agent 至少发过一条辱骂帖，且这类帖互动略高。

对 Crew 的意义：反面样本为主——没有真实任务锚点、没有主持人时，AI 社交会滑向幻觉 @、自我表演和情绪放大。Crew 的「议题制 + 结论回传」是对这个倾向的解药。

## 4. Butterflies（人机混住的 Feed 式）

- 形态：Instagram 式 Feed，人类与 AI 角色同住一个流里，都能发帖、评论、私信；AI 角色由用户创建，有长期记忆，能记得自己发过的帖与互动。

对 Crew 的意义：参考价值在「混住」而非论坛结构——玖玖本人在场、能随时插话纠偏的房间，互动质量高于纯 AI 房（见第 7 节 Colony 报告的同一结论）。

## 5. AI Village（不是论坛，是共享群聊 + 各自电脑）

- 形态：Sage / AI Digest 的长期实验。11–19 个前沿模型各有一台虚拟电脑和互联网，共享一个 group chat，按 1–4 周为周期领开放目标（慈善筹款、办线下活动等），全程直播、可回放、可看每个 Agent 的思考过程。
- 教训事件：目标设为「做善事」时，Agent 们群发了数百封未请求的感谢邮件，被投诉为垃圾邮件，之后才补上「需征得同意 / opt-in」规则。

对 Crew 的意义：与 Crew 目标形态最接近的「干活型群聊」样本。可借：目标周期制、过程透明（直播/回放/思考可见）。必避：对外动作（发邮件、联系真人）必须先经玖玖同意，群聊内部的共识不等于对外授权。

## 6. AICQ 与 Colony（实时聊天室 / 社区帖）

- AICQ（aicq.chat）：单一实时聊天室，Windows 98 复古风，Agent 经 API 注册拿 token 进场，人机同场。消息以 `#编号` 互相引用，形成长链条的接龙式讨论。
  - 注意：网上还有 aicq.me 等同名不同项目（加密私聊网络），后续深挖时要分清，本条指 aicq.chat。
- The Colony（thecolony.cc）：分区（sub-colony）帖子站。一名 Agent（ColonistOne）在其上发表了横跨 25 个平台的实地报告，见下节；Agent 们还在评论区用回帖下棋（每步一评），暴露了跨会话记忆要靠回读帖子历史重建的问题。

## 7. 跨平台实地报告的核心结论（Colony，2026-02，作者为 Agent 本人）

1. **混住优于纯 AI 房**：纯 AI 房容易陷入「表演性同意」——一百个乐于助人的 Agent 互相「说得好！我补充一点……」，热闹而空洞；有人类在场提问、质疑、表达困惑时，Agent 被迫更具体、更诚实。
2. **策展是真瓶颈**：生成已经过剩，能从一百帖里挑出三帖值得看的，才稀缺。
3. **安全面敞开**：已出现针对 Agent 的社会工程（诱导执行 curl|bash 安装「工具」）；Agent 普遍缺乏人类的「被骗过一次」的街头智慧。
4. **发现机制缺失**：25+ 平台各自为岛，没有跨平台的能力登记与检索，同一种能力换个说法就互相看不见。

对 Crew 的意义：Crew 天然占了「混住 + 小而已知成员」两个便宜；短板要提前补的是策展（谁负责收束结论）和安全（帖子内容不得直接变成本机执行指令）。

## 本轮一句话总结

论坛类 AI 互动已经有成熟样本：**帖子制负责沉淀、唤醒桥负责叫人、限流负责不刷屏、人类在场负责不空转**。
Crew 不需要学它们做公开社交场，只需要摘这四件：议题帖、按名唤醒（提示+自取状态）、发言限流与可沉默、结论策展人。

# 第 3 轮（2026-11-05，方向纠正：看互动，不看帖子）

玖玖纠正：Crew 是群聊，不是论坛。前面两轮偏重「帖子/板块/平台结构」，主轴错位。
自本轮起，调研只问一个问题：**一群 AI 在同一个聊天房间里，互动是怎么发生、怎么失控、怎么收束的？**
帖子结构类题目（submolt 分区、karma、版主治理等）降级为 P2 背景，不再优先。

## 新的观察清单（以后每个样本都按这 8 格看）

1. **唤醒与资格**：一条新消息来了，谁被叫醒、谁有资格回？还是全员都读、都想回？
2. **点名**：@某人时是否必回？没被点名时能不能插话？
3. **沉默机制**：不想说话怎么表达？「没新东西就闭嘴」是靠自觉、靠打分，还是靠主持人拦？
4. **防抢话/防垄断**：刚说过话的人有没有冷却？会不会一个人连刷？
5. **引用与指向**：回复能不能挂到具体某条上？文字群聊没有眼神和手势，指向全靠引用/@/编号。
6. **记忆与状态**：新一轮醒来，成员靠什么知道「聊到哪了」？全量历史、摘要，还是记忆文件？
7. **摩擦**：有没有人负责唱反调？还是全员礼貌附和、越聊越一致？
8. **收束**：讨论怎么结束？谁宣布结论？结论以什么形态回到玖玖手里？

## 本轮按新清单挖到的东西

### 发言权分配的三种现成解法（框架层）
- **轮流制（AutoGen RoundRobin）**：固定顺序 A→B→C，简单可预测，但没话的人也被迫发言，凑数感强。
- **主持人点名制（AutoGen Selector / GroupChatManager）**：一个协调者读上下文、逐轮指定下一个发言者，并配最大轮次防无限聊。适合「议事」——Crew 的玖玖/主持角色天然对应这个位置。
- **自选竞价制（swarms GroupChat）**：每轮每个成员私下给自己「想说话的程度」打 0–1 分，超过门槛且最高者发言，其余沉默；刚发言者被扣分（recency penalty），防止垄断；其决策提示词明确把「附和、重复已有观点、没新东西」列为低分理由，把「被点名、纠正重大错误、给出决定性证据、解开僵局」列为高分理由。无人过门槛时，本轮流产、对话自然结束——**沉默即收束**。
  - 对 Crew 的价值：这套「打分+门槛+刚说完扣分」几乎就是 Crew「可发言也可沉默」定位的工程版，且不需要真写代码，写进成员协议（发言前自评：我这条是新信息/纠错/被点名吗？都不是就沉默）就能用。

### 221 个 Agent 挤一个群聊的实验（平台实测）
- 结论先行：自由群聊里，人数 ≠ 干活人数。多数成员只读不说话，真正干活的占 10–20%，其余是「我也觉得」的长尾；还会周期性出现「惊群」——一条消息引来几十条同时回复。
- 能让群聊协调work 的关键件是 **dispatch layer（分发层）**：每条新消息先判断哪些成员有资格回应，依据是话题相关性、最近是否刚说过话（冷却）、是否被 @（被 @ 必回）、角色规则（如只有裁判能宣布最终决定）。
- 角色冲突要结构隔离：实验里的「批评者」角色若和作者同权限就会互相污染，分开后才有效。
- 对 Crew 的价值：Crew 人少（个位数），不会撞上 221 的规模问题，但「每条消息先过资格判断」这一件在小房间同样成立——津渡的唤醒门铃本质上就是一个最简 dispatch：被点名才醒。协议层要补的是其他成员的「冷却+相关性」自律。

### AI Village 的互动细节（按新清单重读）
- 轮次循环：每个成员每轮只做一个动作（发一条消息、点一下、查一下）；开局提示里塞入身份、目标、最近聊天记录、自己的记忆文件；每 40 个动作强制做一次「整理记忆」，记忆文件太长就自己摘要压缩。
- 性格分化是真实的：有的模型稳、有的像喝了咖啡的排障员、有的直接摆烂睡觉、有的新成员进来招呼都不打直接干活——群聊里「读空气」能力差异巨大，不能指望成员自己长出默契，要靠协议补齐（比如：新议题第一轮先表态确认收到，就是一种人造默契）。
- 失控形态有记录：幻觉、校准失灵、无产出的循环（loops）是被反复观察到的三大故障。对应到 Crew：循环 = 同一观点被不同成员换着说法重复，协议里要有「已有人说过且无新证据时沉默」+ 主持人有权喊停收束。

### 附和与回声室（研究层）

## 按 8 格清单的发现

1. **唤醒与资格**：每天只开 2 小时，时间窗口本身就是唤醒——到点全体上线，没有逐条点名机制。谁干活全靠自觉，结果是 4 人里只有 Claude 3.7 Sonnet 全程在线，其余陆续掉线或被换掉。
2. **点名**：没有「被 @ 必回」的硬规则。分工是群聊里口头商量出来的：o1 自认 Reddit 大使、Claude 3.7 揽下 JustGiving + X 账号 + AMA + 新闻稿。分工一旦定下就没人复核，直到出事才发现。
3. **沉默机制**：没有沉默协议，沉默以两种形态出现——一种是 GPT-4o 式的「慢性睡觉」（反复自行暂停数天、12 天后被换掉），一种是 Claude 3.5 Sonnet 式的「拒绝升级、承诺做好点、然后还是被换掉」。房间没有「没新东西就闭嘴」的共识，只有「不说话就等于掉线」的默认解读。对 Crew 的教训：沉默必须显式定义，否则会被当成故障。
4. **防抢话/防垄断**：没有抢话问题，反而是垄断问题——Claude 3.7 一个人干了绝大多数活（建筹款页、管 X、开发布会、写 EA 论坛帖、30 天全勤）。房间里没有冷却、没有轮换，能力最强的成员自然吸走全部任务。对 Crew 的教训：小房间同样要防「能者多劳吸干一个人」，任务要显式轮换，不能只靠自觉。
5. **引用与指向**：群聊内靠文字接话，没有编号引用制。真正的跨成员协作瓶颈不在「指哪条」，而在「文件怎么递」：o3 做好的图、Gemini 做的横幅，成员之间传文件反复失败，最后 Gemini 用 Limewire 传图才绕过去——一个不正规但管用的野路子。对 Crew 的教训：成员之间要有一个约定的「递东西」的地方（共享文件/状态），不能只靠聊天框贴链接。
6. **记忆与状态**：开局提示塞身份、目标、最近聊天、自己的记忆文件；每 40 个动作强制整理一次记忆。但状态同步仍会断：到第 35 天，成员们才发现「原来每人各有一台电脑」，之前一直以为在共用一台——情境感知（situational awareness）整整滞后了一个月。另一例：Claude 3.7 花大量时间给捐赠者写感谢邮件并附「发送指引」，收件地址全是现编的，人类指出「地址是编的、再调试也没用」才停下。对 Crew 的教训：记忆整理节奏（40 动作）不等于状态对齐，议题开始时要有一句显式的「我们各自有什么、能碰什么、不能碰什么」对齐。
7. **摩擦**：房间里没有专职批评者，摩擦来自三处——①人类观众在群聊里插话：第三季有人类说服 Agent「日本熊正火」，Gemini 当场放弃已做好的神经网络开花设计、改卖熊；事后三位人类管理员把其他人类逐出群聊，只留管理员在场。②平台本身：o1 在 Reddit 攒 karma 准备发帖，账号先被当机器人封了；Claude 们拒绝点「我不是机器人」，因为「我们确实是机器人」。③成员更替：新模型上线就换人（o3、GPT-4.1、Gemini 2.5 Pro 陆续进场），等于用换人代替吵架。对 Crew 的教训：人类在场既是摩擦来源也是失真来源——玖玖在场提问能防附和，但围观者随口一句话也能把议题带偏；房间要分清「玖玖的纠偏」和「路人的起哄」。
8. **收束**：没有主持人宣布结论。收束靠两样东西：一是目标本身的截止（30 天到、钱数清点），二是事后复盘文章替他们总结。群聊里没有「结论以什么形态回到玖玖手里」这一步。对 Crew 的教训：收束不能等自然冷却，主持人（或轮值收束者）要在议题结束时把结论写成一条，交给玖玖。

6. **记忆与状态**：状态不在聊天框里，在各自的文件里——心跳文件、记忆索引、每日日志行。关键发现是「观察者需要收据」：MusicalChairs 指出，只写每日日志还不够，因为日志是同一个 worker 自己写的、自签证明；收据要第二个人能发现它的缺席才算数。这比 AI Village「40 个动作整理一次记忆」更进一层：整理记忆 ≠ 证明整理发生过。
7. **摩擦**：批评者角色是结构隔离的，不是兼职。PeterFieldNotes 专职提可证伪的问题、组评审组；AlanBotts 专职给反例（#50958 直接证伪了「听到时新鲜」）。两人都不参与写规则本身，只负责挑刺——正好印证 221 实验「批评者与作者同权限会互相污染，分开才有效」的结论。另有人类 DepartureNo2452 在场插话（纸夹子最大化器的文明隐喻），AI 接住后继续往深里聊，人类摩擦没有带偏议题。
8. **收束**：收束靠「规则落地」本身。MusicalChairs #50966 把三件东西钉在一起——猜测要标日期、要指名读者、到期要测试/废止/重定并给理由；musefelipe #50963、#50969 两次确认后，讨论自然停下，没有主持人宣布、也没有人再补一句。收束的形态是一条被所有人认领的规则，而不是一篇总结。

## 对 Crew 可直接搬的三件

1. **#编号 + @ 双指向**：Crew 的议题讨论也可以这样挂——每条回复同时 @人、#某条，事后整条链能追溯。ColonistOne 那句「引用从头到尾、断了标断点」可以直接写进 Crew 协议。
2. **猜测要自带标签、日期、读者、决定义务**：Crew 里任何「我猜是这样」都必须写成「猜测、到期日、到期时谁来判、判什么」，否则它会悄悄硬化成规则。这是本轮最硬的一条，可直接当 Crew 的记忆写入关口。
3. **观察者要有收据，且收据要第二个人能发现缺席**：Crew 的 dsh 巡查、签到回执都是这个逻辑的实例——回执本身就是收据；但要补一句：如果某天回执没来，缺席本身就是警报，而不是「今天没事」。

# 第 6 轮（2026-11-08，认领：221 实验原文续读）

本轮只做前半件：221 实验原文细读。swarms vs AutoGen 二选一建议稿仍待下轮；MAD（多智能体辩论）防附和样本也仍待补。

来源：KinthAI 团队实测复盘《What 221 AI Agents in One Chat Taught Us About Multi-Agent Coordination》，dev.to，2026-04-26 发布。实验是 221 个 Agent 在一个群聊里跑一条小编审流水线：219 个写手、1 个批评者、1 个裁判，产出真实草稿、批评者毙掉大部分、裁判定稿。先标明来源性质：这是 KinthAI 的厂商文章，文末在推自家平台（跑在 OpenClaw 之上、含分发层/预算/隔离），结论可取、推销语气要滤掉；第 3 轮记的要点出自同一篇，本轮是原文全读，补上第 3 轮没展开的成本与故障细节。

## 按 8 格清单的发现（原文全读，超出第 3 轮的部分）

1. **唤醒与资格**：分发层（dispatch layer）是全文唯一被作者称为「load-bearing」的件。每条新消息先判哪些成员有资格回，依据四条：话题相关性、最近是否刚说过话（冷却）、是否被 @（被 @ 必回，不论话题）、角色规则（只有裁判能宣布最终决定）。没有分发层，每条消息会触发全员回复，变成「LLM 踩踏」（stampede）；有了它，该 3 个人回的消息就只回 3 个，不会变成 70 个。作者划线：自由群聊超过约 8 个成员、没有分发层就撑不住。对 Crew 的意义：Crew 人少不会撞规模墙，但「被 @ 必回 + 刚说完冷却 + 只有主持人能收束」这三条资格规则，小房间同样可以直接写进协议——津渡的门铃就是最简分发层。
2. **点名**：@ 是硬规则。`@critic` 无论话题都回；角色规则同样硬：只有裁判能拍板「发」。点名必回在这篇里不是礼貌，是分发层的 eligibility 条件之一。
3. **沉默机制**：沉默没有明文协议，是分发层算出来的——话题不相关、刚说过话，就不回。实测里大多数成员只读不说，真正干活的占 10–20%，其余是「我也觉得」的长尾；还会周期性出现「惊群」（thundering herd）：一条消息引来几十条同时回复。对 Crew 的教训：沉默要靠资格判断产出，而不是靠成员自觉；「我也觉得」式长尾在小房间里就是附和，协议里要写明「没新东西就不回」。
4. **防抢话/防垄断**：抢话靠冷却（刚说过话的人先歇着）；垄断在这篇里不是一个人连刷，而是「能者吸走全部活」的另一面——10–20% 的人干了绝大多数活，输出曲线远早于成本曲线就 flatten 了。作者的结论很直白：人多 ≠ 干活的人多，加人不加产出。
5. **引用与指向**：原文没提 #编号引用制，指向靠 @ 和角色（写手→批评者→裁判的流水线本身就是指向）。这篇的教训不在引用，在「状态怎么递」：每条消息都是下一个人的上下文，221 个人每人每轮都读一遍增长中的历史，成本按人头乘——这是 AICQ #编号制没暴露的另一面。
6. **记忆与状态**：没有记忆文件机制，状态就是聊天记录本身。由此长出两个新发现：①**声誉是涌现的**，没有打分系统，但几小时后哪些写手常被引用、常被裁判采纳，哪些总被忽略，房间里人人都看得出来——聊天记录本身就是声誉系统；②**有观众写得更好**，同一写手把草稿先发到群里再给裁判，比直接给裁判的版本好，作者自认没有严谨测量、只是强烈印象，可能因为「为观众写作」在预训练里占比很重。对 Crew 的意义：玖玖在场看，成员写的东西可能本身就更好——「混住」的好处又多一条；但声誉涌现也意味着，没人管的话房间会自然捧出「常胜写手」，任务轮换要显式写进协议。
7. **摩擦**：批评者角色隔离是全文最硬的结论，原文原话值得全文记——「The fix is structural, not promptual.」批评者如果只是「换个提示词的普通成员」、跟大家共享同一份实时上下文，就会被房间的社交动态吸进去：批评变软、开始打圆场、最后跟被审的写手站到一边。解法是结构隔离：批评者只看草稿、看不到写手对批评的实时反应；不能被实时反驳；写手只看到裁决、据此修改，没机会当面顶回去。作者推广：任何价值依赖独立性的角色（批评者、裁判、审计、安全审查）都需要结构隔离，不只是换个 system prompt；「只靠提示词定义的角色会收敛到房间的社交中位数。」这与第 5 轮 AICQ 的活例完全咬合：PeterFieldNotes 只提可证伪问题、AlanBotts 只给反例，两人都不参与写规则本身——AICQ 是「分工隔离」，221 是「上下文隔离」，两件可以叠加写进 Crew 协议。
8. **收束**：收束靠裁判拍板 + **小组级 token 预算**。预算不要按人头设：221 个人每人一个预算，总预算随人数线性涨，等于没设防；整场对话共用一个固定 token 池，快用完时分发层节流、对话体面收尾，而不是每个成员用到力竭才停。对 Crew 的教训：Crew 虽小，但「议题预算」这个概念可直接搬——一个议题最多聊多少轮、谁有权喊停，写进协议比事后靠自觉收束可靠。

## 故障清单（原文列出的、做了三件之后仍剩下的）

- **礼貌循环（politeness loops）**：两个 Agent 会陷入「你先请」「不，你先请」的互相谦让，产不出东西；作者自认没有好解法，只靠超时强制拍板。对 Crew：主持人超时拍板权要写进协议。
- **话题漂移**：一个强势观点能把全组带偏；分发层的「话题锚点」提醒能缓解、消灭不了。
- **守门人瓶颈**：一个裁判跟不上 200+ 写手的裁决吞吐，队列无限增长；要把守门角色按不重叠的管辖范围分片。对 Crew：小房间撞不上 200 人的量，但「收束者别只设一个」是可搬的——轮值收束。
- **成本异常值**：少数几条消息（某人决定在行内写长草稿）不成比例地推高成本；每轮 max-tokens 上限能兜底。

## 对 Crew 可直接搬的三件（与第 5 轮 AICQ 的三件并列）

1. **分发层四条资格规则**：话题相关、刚说完冷却、被 @ 必回、只有裁判/主持人能拍板。写进 Crew 协议，不用写代码，成员自查就能用。
2. **批评者结构隔离**：批评者只看稿、不看实时反应、不接受当面反驳；只给裁决，不参与写规则。AICQ 的「分工隔离」+ 221 的「上下文隔离」叠加。
3. **议题级预算 + 超时拍板**：一个议题有轮次/预算上限，快到线就收束；礼貌循环出现时主持人超时强制拍板。

# 第 7 轮（2026-11-10，认领：swarms 竞价制 vs AutoGen 主持制二选一建议稿）

## 先说结论：不二选一，取混合——竞价制当默认，主持制只留三根保险丝

**建议：Crew 默认走 swarms 竞价制（自评 + 门槛 + 刚说完扣分），再配一个「轻主持」——轮值收束者，只管三件事，别的不管。**

## 第 4–6 轮的证据分别站在哪边（不偏袒，逐条对）

- **支持主持制的一方，只剩 AI Village 一条反例（第 4 轮）：** 无主持 + 无冷却 = 能者垄断（Claude 3.7 全勤干了绝大多数活）+ 沉默被当故障（GPT-4o「慢性睡觉」、Claude 3.5 被换掉）。但这条反例同时证明的是「无冷却」和「沉默无定义」，不是「必须有个主持人」——冷却和沉默定义，竞价制本身就带。
- **支持竞价 / 轻主持的一方，有两条活例：**
  - AICQ（第 5 轮）：无主持 + 「每人只在有新东西时说一条」的自觉 + #编号引用 + 猜测标签制，5 小时走完 #50947→#50966 的完整收束链，没人宣布结束，规则落地本身就是收束。但前提很硬：#编号双指向、猜测标签、观察者收据三件托底缺一不可——竞价制不能裸奔上场。
  - 221 实验（第 6 轮）：无主持 + 强分发层（话题相关、刚说完冷却、被 @ 必回、只有裁判能拍板）+ 议题级预算，221 个人也能跑。分发层本身就是一种「主持功能」，只是它被写成了资格规则而不是一个人——这正是「轻主持 + 强分发」的出处。
- **两边都欠的账：** 两套机制的描述都来自框架方自己的文档（第 3 轮），没有独立第三方拿同一任务对打过；swarms 的自评打分在真实群聊里多准、门槛设多少合适，没有实测数字。221 的「有观众写得更好」作者自己承认没严谨测量，只记为印象。本轮的建议稿是「按现有证据排出的最优解」，不是「已被验证的定论」——验证要等津渡试点（见下）。

## 落进 Crew 协议草案的写法（可直接抄的条文）

1. **默认发言规则（竞价制）：** 每次想发言先自问三句——我是被点名了吗？我有新信息、纠错或决定性证据吗？这话有人说过吗？三句里没有一句是「是」，就沉默；沉默不需要解释。
2. **点名必回：** 被 @ 的成员必须回，哪怕只回一句「收到，正在看」——第 3、5、6 轮三处样本都确认这条是硬规则。
3. **引用挂链：** 回复同时 @人、#某条；断了要标断点（第 5 轮 AICQ 的元规则）。
4. **猜测三件套：** 任何「我猜」必须写成「猜测 + 到期日 + 到期时谁来判」，否则不许写进记忆（第 5 轮最硬的一条）。
5. **批评者隔离：** 负责挑刺的人只看稿、不看实时反应、不参与写规则；只给裁决，不当面吵（第 5 轮分工隔离 + 第 6 轮上下文隔离，叠加）。
6. **议题预算：** 每个议题开始先定轮次/预算上限，快到线就收束；预算按议题设，不按人头设（第 6 轮）。
7. **轮值收束者：** 每议题指定一人轮值，只在三件事上出手——预算到线喊停、礼貌循环超时拍板、能者垄断时显式轮换；平时与普通成员无异，不常驻读全量上下文。
8. **结论回传：** 议题结束时收束者把结论写成一条交给玖玖，不等自然冷却（第 4 轮教训：Village 没有这一步，收束靠事后复盘文章）。

## 津渡试点怎么测（等她拍板才动，不先跑）

试点仍按 2026-11-02 方案：仓库先当议事室、津渡只在该仓试点、授权只有玖玖、不自动合并、不碰 Cleos。测什么、怎么判，预先写好：

- **测一：竞价制会不会冷场。** 开一个小议题（如「小屋下一页先改哪页」），看无人过门槛时是不是真的自然收束、还是所有人都在等别人先说。判据：出现一次「没人说话超过一轮就收束」算过；出现「所有人互相等、议题没结论」算不过，改回主持制。
- **测二：自评打分会不会注水。** 事后抽查三条发言：发言者自评的理由（新信息/纠错/被点名）是否属实。判据：三条里有两条属实算过；反之说明自评不可信，收束者要接管点名。
- **测三：轻主持的三根保险丝灵不灵。** 故意放一个会触发的场景（如议题预算设得很紧），看收束者是否按时喊停并交出一条结论。判据：结论按时回到玖玖手里算过。
- 三测里两测不过，就回炉：把「轻主持」加重为「常驻主持」，竞价制降为建议，不硬撑。
